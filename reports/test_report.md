### 개발·시험 중 발견하고 수정한 문제

#### FAIL-01
- 문제: 다른 이미지 폴더의 같은 이름 이미지 결과가 연동되어 표시됨
- 원인: 파일 이름만으로 저장 결과를 찾음
- 조치: label_status.csv 에 source(원본 폴더) 칸 추가, 연 폴더 안의 TXT 만 표시
- 재시험: PASS

#### FAIL-02
- 문제: 원본 폴더를 열면 다른 폴더에 저장된 EDITED 배지·작업자 이름이 표시됨
- 원인: 라벨과 달리 검수 기록은 결과 폴더 기록을 그대로 사용
- 조치: 결과 폴더를 열었을 때만 기록 표시 (display_meta)
- 재시험: PASS

#### FAIL-03
- 문제: Ctrl+Shift+Z 를 누르면 Redo 가 아니라 Undo 가 실행됨
- 원인: Shift 를 누르면 대문자 Z 로 입력되는데 대문자 Z 도 Undo 에 연결돼 있었음
- 조치: 글자 대신 Shift 눌림 여부로 Undo / Redo 구분 (Caps Lock 영향 없음)
- 재시험: PASS

#### FAIL-04
- 문제: 작업자 REVIEW 저장 시 review 폴더에 노트만 저장되고 이미지가 없음
- 원인: REVIEW 결과의 저장 폴더가 노트 폴더로만 지정됨
- 조치: 작업자/review/ 에 이미지 + 라벨 + <이름>_리뷰노트.txt 함께 저장
- 재시험: PASS

#### FAIL-05
- 문제: 리뷰 노트 TXT 가 YOLO 라벨로 잘못 읽힐 수 있음
- 원인: 노트 파일 이름이 라벨과 같은 <이름>.txt
- 조치: 노트 이름을 <이름>_리뷰노트.txt 로 바꾸고 Validation 짝 검사에서 제외
- 재시험: PASS

#### FAIL-06
- 문제: 검수자가 저장하면 TXT 만 저장되어 결과 폴더를 열 수 없음
- 원인: 설정의 검수자 이미지 복사가 꺼져 있음
- 조치: copy_image.reviewer: true (모든 상태 이미지 + TXT)
- 재시험: PASS

#### FAIL-07
- 문제: 저장 결과 보기 중 같은 이미지 썸네일을 눌러도 원래 화면으로 돌아오지 않음
- 원인: 같은 번호의 이미지는 이동하지 않도록 되어 있음
- 조치: 저장 결과 보기 중이면 같은 이미지라도 다시 불러옴
- 재시험: PASS

#### FAIL-08
- 문제: 키패드 . (Num Lock 꺼짐 = 키패드 Del) 이 박스 삭제로 동작할 위험
- 원인: 키패드 Del 이 삭제 키로 연결됨
- 조치: 시점 이동은 Tab 으로 통합, 단축키 충돌 정리
- 재시험: PASS
